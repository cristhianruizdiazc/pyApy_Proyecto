|---|---|---|---|
| `GET` | `/api/properties` | Público | Obtener catálogo de propiedades públicas activas. |
| `GET` | `/api/properties/:id` | Público | Obtener detalle de propiedad pública. |
| `GET` | `/api/properties/:id/availability` | Público | Verificación autoritativa de disponibilidad ante reservas, bloqueos y owner bookings. |

| `POST` | `/api/reservations` | Público (Rate-limited) | Creación atómica, transaccional e idempotente de reservas en Firestore. |
| `POST` | `/api/reservations/lookup` | Público | Consulta de reserva por localizador y documento. |
| `POST` | `/api/reservations/:id/cancel` | Propietario / Admin / Cliente | Cancelación autoritativa de reserva. |
| `GET` | `/api/sponsors` | Público | Listado de sponsors activos. |
| `POST` | `/api/admin/sponsors/:id/toggle` | Admin | Cambio de estado de sponsor validado en servidor. |
| `GET` | `/api/owner/properties` | Propietario / Admin | Listado de propiedades del anfitrión autenticado. |
| `GET` | `/api/owner/reservations` | Propietario / Admin | Reservas asociadas al anfitrión autenticado. |

| `POST` | `/api/owner/bookings` | Propietario / Admin | Creación de reserva directa con detección de conflictos. |
| `DELETE`| `/api/owner/bookings/:id` | Propietario / Admin | Eliminación de reserva directa. |
| `GET` | `/api/owner/blocks` | Propietario / Admin | Bloqueos de mantenimiento del anfitrión. |
| `POST` | `/api/owner/blocks` | Propietario / Admin | Creación de bloqueo de mantenimiento con validación de solapamiento. |
| `DELETE`| `/api/owner/blocks/:id` | Propietario / Admin | Eliminación de bloqueo de mantenimiento. |
| `POST` | `/api/properties` | Propietario / Admin | Registro de propiedad forzando `verificationStatus: 'pending'`. |
| `GET` | `/api/admin/audit-logs` | Admin | Registros de auditoría inmutables. |
| `GET` | `/api/admin/search-intents` | Admin | Radar de demanda registrado por el buscador. |

> **PREGUNTA 1:**  
> *"Si elimino completamente MarketplaceService, StorageService, AvailabilityService y todos los SEED_* del frontend, ¿la aplicación sigue funcionando?"*

> **PREGUNTA 2:**  
> *"Si Firestore contiene una reserva o bloqueo real, ¿el buscador puede mostrar esa propiedad como disponible porque React no recibió una copia local?"*  
> **RESPUESTA: NO.** La disponibilidad se evalúa exclusivamente en el backend (servidor Node/Express consultando Firestore/Adapter). React únicamente renderiza la respuesta devuelta por `POST /api/search` o `GET /api/properties/:id/availability`.
